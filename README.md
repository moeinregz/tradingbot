# ربات معامله‌ی پله‌ای USDT/IRT نوبیتکس

ربات خودکار خرید و فروش پله‌ای تتر روی نوبیتکس، با داشبورد، حالت آزمایشی، توقف اضطراری و ورود دومرحله‌ای.
همه‌چیز (داشبورد، API و موتور معاملاتی) در یک پروژه‌ی **Next.js + TypeScript** است تا مستقیم روی **Vercel** بالا بیاید.
داده‌ها در **MongoDB Atlas** (پلن رایگان M0) نگه داشته می‌شوند. کل سیستم رایگان است: Vercel Hobby + Atlas M0 + cron-job.org.

> طبق مشخصات شما بک‌اند FastAPI/Python بود. چون Vercel سرور همیشه‌روشن ندارد، موتور معاملات به TypeScript
> نوشته شد و روی همان توابع Serverless اجرا می‌شود. یک زمان‌بند (Cron) هر دقیقه موتور را صدا می‌زند و هر
> فراخوانی چند «تیک» اجرا می‌کند (پیش‌فرض ۳ تیک با فاصله‌ی ۱۵ ثانیه).

## استراتژی (همان چیزی که پیاده شده و تست دارد)

| پله | خرید: فاصله پایین‌تر | سهم ریال آزاد | فروش: فاصله بالاتر | سهم تتر آزاد |
|---|---|---|---|---|
| ۱ | ۲٪ | ۱۵٪ | ۲.۵٪ | ۲۰٪ |
| ۲ | ۴٪ | ۲۰٪ | ۵٪ | ۲۵٪ |
| ۳ | ۷٪ | ۲۵٪ | ۸٪ | ۲۵٪ |
| ۴ | ۱۰٪ | ۴۰٪ | ۱۲٪ | ۳۰٪ |

- شروع چرخه: هر دو نردبان از قیمت میانی بازار ساخته می‌شوند.
- وقتی بهترین قیمت فروشنده (ask) به قیمت یک پله‌ی خرید برسد، سفارش limit همان پله ثبت می‌شود؛ حجم = درصد پله × **ریال آزاد همان لحظه**.
- وقتی بهترین قیمت خریدار (bid) به قیمت یک پله‌ی فروش برسد، فروش با درصد پله × **تتر آزاد همان لحظه** ثبت می‌شود.
- اجرای خرید پله‌های دیگر را جابه‌جا نمی‌کند.
- اجرای هر فروش **فقط نردبان خرید** را از قیمت اجرای همان فروش از نو می‌سازد؛ پله‌های فروش باقی‌مانده ثابت می‌مانند (حتی اگر قیمت بی‌وقفه بالا برود).
- بعد از اجرای آخرین پله‌ی خرید، خرید قفل می‌شود تا یک فروش انجام شود.
- بعد از اجرای آخرین پله‌ی فروش، چرخه‌ی جدید از قیمت همان فروش شروع می‌شود.
- سفارش اجرانشده بعد از «مهلت سفارش» (پیش‌فرض ۳۰ دقیقه) لغو و پله دوباره فعال می‌شود؛ اگر بخشی اجرا شده باشد پله اجراشده حساب می‌شود.
- سفارش زیر حداقل ارزش (پیش‌فرض ۳۰۰ هزار تومان) ثبت نمی‌شود.
- سود محقق‌شده با میانگین بهای تمام‌شده محاسبه می‌شود و کارمزدها (تتری در خرید، ریالی در فروش) لحاظ شده‌اند.

همه‌ی درصدها، تعداد پله‌ها (۱ تا ۱۰) و پارامترها از صفحه‌ی «تنظیمات» قابل تغییرند.

## امنیت و پایداری

- **حالت آزمایشی (Paper):** قیمت واقعی نوبیتکس (یا قیمت شبیه‌سازی‌شده)، موجودی و معاملات مجازی. پیش‌فرض همین حالت است.
- **حالت واقعی** فقط وقتی فعال می‌شود که `LIVE_TRADING_ENABLED=true` باشد، توکن تنظیم شده باشد و کد ۲FA وارد شود.
- **توقف اضطراری:** همه‌ی سفارش‌های باز لغو و ثبت سفارش جدید متوقف می‌شود.
- **ورود:** نام کاربری + رمز (bcrypt) + کد TOTP (Google Authenticator). ۵ تلاش ناموفق = قفل ۱۵ دقیقه‌ای. کوکی httpOnly و محافظت CSRF.
- **جلوگیری از سفارش تکراری:** هر سفارش یک `clientOrderId` یکتا دارد و **قبل از ارسال** در دیتابیس ثبت می‌شود. اگر جواب صرافی گم شود، تیک بعد سفارش با همان شناسه پیدا یا با همان شناسه دوباره ارسال می‌شود (صرافی شناسه‌ی تکراری را رد می‌کند).
- **قفل موتور** در دیتابیس تا دو اجرای هم‌زمان (Cron + دکمه) با هم تداخل نکنند.
- **قطعی اینترنت/صرافی:** خطاهای شبکه، ۴۲۹ و ۵xx با تلاش مجدد مدیریت می‌شوند و وضعیت دست نمی‌خورد؛ خطاهای غیرقابل‌تکرار (مثل توکن نامعتبر) پس از چند بار پیاپی ربات را متوقف می‌کنند.
- **بازیابی پس از Crash:** کل وضعیت (نردبان‌ها، سفارش‌های باز، موقعیت، سود) در MongoDB است و تیک بعد از همان‌جا ادامه می‌دهد.
- **کلید API بدون مجوز برداشت:** در پنل نوبیتکس توکن را **فقط با دسترسی معامله** بسازید. ربات هیچ endpoint برداشتی صدا نمی‌زند.

## راه‌اندازی روی Vercel

1. **دیتابیس (رایگان):** در [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) یک کلاستر **M0 Free** بسازید.
   - Database Access: یک کاربر با رمز بسازید (نقش readWrite کافی است).
   - Network Access: آدرس `0.0.0.0/0` را اضافه کنید (IP سرورهای Vercel ثابت نیست؛ امنیت با رمز کاربر دیتابیس است).
   - Connect → Drivers: رشته‌ی اتصال `mongodb+srv://...` را بردارید و در `MONGODB_URI` بگذارید.
   - کالکشن‌ها و ایندکس‌ها خودکار ساخته می‌شوند. گزارش‌ها بعد از ۳۰ روز و قیمت‌ها بعد از ۱۴ روز خودکار پاک می‌شوند (TTL) و قیمت هر دقیقه یک رکورد است، پس فضای ۵۱۲ مگابایتی رایگان پر نمی‌شود.
2. **پروژه‌ی جدید در Vercel** (پلن رایگان Hobby) بسازید و مخزن `tradingbot` را Import کنید.
3. متغیرهای محیطی را طبق `.env.example` تنظیم کنید. حداقل:
   - `MONGODB_URI`، `SESSION_SECRET` (حداقل ۳۲ کاراکتر)، `ADMIN_USERNAME`، `ADMIN_PASSWORD_HASH`، `CRON_SECRET`
   - هش رمز: `npm run hash-password -- "رمز قوی"`
4. Deploy کنید، وارد شوید، QR را با برنامه‌ی Authenticator اسکن کنید.
5. **زمان‌بند:** پلن رایگان Vercel فقط Cron روزانه دارد، پس یکی از این‌ها:
   - **cron-job.org (رایگان):** هر ۱ دقیقه `GET https://<دامنه>/api/cron/tick` با هدر `Authorization: Bearer <CRON_SECRET>`.
   - **Vercel Pro:** فایل `vercel.json` با `{"crons":[{"path":"/api/cron/tick","schedule":"* * * * *"}]}` بسازید (Vercel خودش هدر `CRON_SECRET` را می‌فرستد).
6. چند روز در حالت آزمایشی اجرا کنید. اگر نتیجه خوب بود: `LIVE_TRADING_ENABLED=true` + `NOBITEX_API_TOKEN`، Redeploy، و از «تنظیمات» با کد ۲FA به حالت واقعی بروید.

### ⚠️ دسترسی سرورهای Vercel به نوبیتکس

سرورهای Vercel خارج از ایران هستند و نوبیتکس ممکن است درخواست‌های IP خارجی را مسدود کند. اول در حالت آزمایشی
ببینید قیمت می‌آید یا نه (اگر نیاید، خطا در داشبورد نمایش داده می‌شود). اگر مسدود بود:
- همین پروژه را روی یک VPS ایرانی با `npm run build && npm start` اجرا کنید (هر سرور Node.js کار می‌کند) و Cron را با `curl` روی همان سرور بگذارید، یا
- `NOBITEX_BASE_URL` را به یک پراکسی معکوس روی سرور ایرانی بدهید.

برای دیدن داشبورد بدون دسترسی به نوبیتکس: `PAPER_PRICE_SOURCE=simulated`.

## اجرای محلی

```bash
cp .env.example .env.local   # مقادیر را پر کنید
npm install
npm run dev                   # http://localhost:3000
npm test                      # تست‌های استراتژی
```

یک تیک دستی: دکمه‌ی «اجرای تیک» در داشبورد، یا:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/cron/tick
```

## ساختار

```
src/lib/engine.ts            موتور: تیک، تطبیق سفارش‌ها، ثبت پله‌ها، سود/زیان، توقف اضطراری
src/lib/strategy.ts          ساخت نردبان‌ها، چرخه، شناسه‌ی یکتای سفارش
src/lib/exchange/nobitex.ts  کلاینت API نوبیتکس (قیمت، موجودی، ثبت/وضعیت/لغو سفارش)
src/lib/exchange/paper.ts    صرافی آزمایشی
src/lib/store/db.ts          MongoDB: وضعیت، سفارش‌ها، گزارش‌ها، قیمت‌ها، قفل
src/lib/runtime.ts           اتصال همه‌چیز + قفل + مدیریت خطا
src/app/api/*                API داشبورد و /api/cron/tick
src/app/*                    داشبورد، سفارش‌ها، گزارش‌ها، تنظیمات، ورود
tests/engine.test.ts         تست قوانین استراتژی
```

## نکته‌های مهم

- endpointهای نوبیتکس طبق مستندات عمومی آن پیاده شده‌اند (`/v3/orderbook/USDTIRT`، `/users/wallets/list`،
  `/market/orders/add|status|update-status`). قبل از حالت واقعی، یک بار با مبلغ کم امتحان کنید.
- `حداقل ارزش سفارش`، `گام قیمت` و `اعشار مقدار` را با قوانین فعلی بازار USDTIRT نوبیتکس تطبیق دهید.
- اگر تتر نداشته باشید و قیمت بالا برود، پله‌های فروش اجرا نمی‌شوند و نردبان خرید جابه‌جا نمی‌شود (طبق
  استراتژی). در این حالت با «چرخه‌ی جدید» نردبان‌ها را از قیمت فعلی بسازید.
- این نرم‌افزار توصیه‌ی مالی نیست؛ مسئولیت معاملات واقعی با خودتان است.
